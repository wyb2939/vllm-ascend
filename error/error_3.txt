  探针精确定位：
  1. 第 3 chunk 的 layer 0（linear_attention/GDN）输入干净、输出全 NaN
  2. GDN 的 cache_indices=[3] 指向的 conv/ssm state 槽位已被写成 NaN（第 2 chunk 时还是干净的 0）
  3. [TENSORS]：4 个 KV cache tensor 全部 offset=0
  4. [HB]：full-attn 组（layers 3,7,11…）与 Mamba 组（layers 0,4,8…）的 start 完全相同，映射到同一段内存

  根因

  _allocate_kv_cache 的 hybrid 分支给所有 cache group 分配一份 hybrid_backing，各组 tensor 的 offset 都是 0（上游设计：overlay   别名是安全的，前提是同一 block id 在所有组里落在同一物理偏移，即 block_size/page 布局必须一致）。

  - BF16：full-attn 和 Mamba 的 block_size 都是 896 → 满足前提 → 正常
  - C8_PTH：c8_pth_cache_spec 通过 state_content_bytes 把 full-attn page 从 1835008 缩到 1730560，但 _align_hybrid_attention_page_sizes 只对齐   FullAttentionSpec/SlidingWindowSpec，不处理 MambaSpec。结果：
    - full-attn: blk=1664, page=1730560
    - Mamba: blk=8192, page=1730560 (padded from real=1603584)
    - block_size 不同 → 同一 block id 落到不同 token 偏移 → full-attn 写 KV 时踩掉 Mamba 的 conv/ssm state → 下一个 chunk 的 GDN 读到 NaN

  这也解释了为什么"单 chunk 正常"：单 chunk 时 Mamba 状态还没被跨 chunk 复用，踩踏不显现。
