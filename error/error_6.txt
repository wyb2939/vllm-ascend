  为什么对齐 block_size 仍不够（决定性算术）

  探针确认 4 个 tensor 全部 offset=0、layer_stride=2599301120、num_blocks=1502、page=1730560，即注意力组和 Mamba 组仍覆盖同一段 layer 切片 [3L,   4L)。在同一个切片内，两组的 block id → 字节映射不同：

  ┌────────────────────────────┬───────────────────────────────────────────────────────┐
  │                            │            每个 scheduler block 的物理跨度            │
  ├────────────────────────────┼───────────────────────────────────────────────────────┤
  │ C8 注意力（section-major） │ K 段连续，block b 的 K 在 b × 851968（=13×128×2×256） │
  ├────────────────────────────┼───────────────────────────────────────────────────────┤
  │ Mamba                      │ block b 的 state 在 b × 1730560                       │
  └────────────────────────────┴───────────────────────────────────────────────────────┘

  C8 blk 1 K[851968,1703936)  → 落进 mamba page 0
  C8 blk 2 K[1703936,2555904) → 仍落进 mamba page 0   ← 两个 C8 block 挤进同一个 mamba page
  C8 blk 3 K[2555904,3407872) → mamba page 1

  section-major 把 K 做成一条连续大数组，block 的物理跨度（851968）只有 scheduler page（1730560）的一半，所以 block id × 跨度 与 Mamba 的 block id    page 根本不是同一坐标系。只要 C8 注意力与 Mamba 共享 backing，这种穿插就必然存在——block_size 相等只是必要条件，不是充分条件。

  修复方向，两条路：

  1. C8 注意力组改用独立 backing（推荐）：在 _allocate_kv_cache 的 hybrid_backing is not None 分支里，对 is_c8_pth_kv_quant 的 FullAttentionSpec   层跳过 hybrid_backing，各自 _allocate_int8_cache_tensor(layer_size)（非 hybrid 分支已有这段逻辑）。Mamba 组继续用 hybrid_backing。代价是注意力 16  层不再与 Mamba 别名，HBM 占用增加（当前可用 38.84 GiB，需实测是否装得下）。
  2. C8 布局改为 page-strided（每 scheduler block 占满 page 字节，内部打包 K/V/scale），使 block b → b × 1730560 与 Mamba 对齐。但这样 stride[0] =   page pitch，FIA tiling 会报 561002（"Non-contiguous cache is supported only by the arch22 regular FAInfer"），风险高。
