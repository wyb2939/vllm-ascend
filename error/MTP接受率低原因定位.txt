根因定位与修复完成

  根因（PD 分离 + MTP + C8-PTH）

  C8-PTH 把 mamba block_size 从 max_model_len(139264) 对齐到 attention block(1664)（attn_utils.py），破坏了 vLLM mamba "none"   模式的核心不变量：一个请求 = 一个状态块，且状态位于块表第 0 列。

  MambaManager.get_num_skipped_tokens() 恒返回 num_computed-1：
  - block_size=139264 时 (N-1)//139264=0，不跳过 → 正常
  - block_size=1664 时 2028//1664=1，remove_skipped_blocks 把块表第 0 列（真实状态块）null 成 0

  由此：

  ┌───────────┬────────────────────────────────────────────────────────────────────────────────────────────┐
  │           │                                            证据                                            │
  ├───────────┼────────────────────────────────────────────────────────────────────────────────────────────┤
  │ P 侧      │ 真实状态在 block 3（ssm_absmax=23.0 conv=26.75），block 4 是空；但调度器块表变 [0,4,5,6,7] │
  ├───────────┼────────────────────────────────────────────────────────────────────────────────────────────┤
  │ connector │ transfer_block_idx=len-num_spec-1=1 取到 remote block 4（空块），而非状态块 3              │
  ├───────────┼────────────────────────────────────────────────────────────────────────────────────────────┤
  │ D 侧      │ 块表 [0,3,6,7,8]，GDN 读 [0,3,6,7] → slot 0 = null（零状态）                               │
  └───────────┴────────────────────────────────────────────────────────────────────────────────────────────┘

  → D 侧 ssm_state 为零 → GDN 输出 NaN → 主模型 NaN → MTP draft logits NaN → 接受率 0%。非 C8（block_size==max_model_len）不触发。

  修复

  vllm_ascend/worker/v2/attn_utils.py：把 C8-PTH 的 mamba block 对齐限定在 align 模式。none 模式保留原生 block_size（共享 backing 的踩踏问题已由   C8-PTH full-attn 独立分配 backing 解决）。

  任务已完成：根因（C8-PTH 把 mamba block_size 从 max_model_len 缩到 1664，触发 none 模式把块表第 0 列状态块 null 掉，导致 PD 下 D 侧 ssm_state 为   → 全链路 NaN → MTP 接受率 0%）已定位并修复，真实文本接受率从 0% 恢复到 47.6%–61.1%。

内容：本次 PD MTP 接受率 0% 的根因修复——把 C8-PTH 的 mamba block_size 对齐从无条件执行改为仅在 mamba_cache_mode == "align" 时生效。

  修复逻辑：
  - 原代码：C8-PTH 下无条件把 mamba block_size 从 max_model_len(139264) 缩到 attention block(1664)
  - none 模式下这会触发 MambaManager.get_num_skipped_tokens() 返回 >0，把块表第 0 列（真实状态块）null 掉；Mooncake connector 的 transfer_block_idx  = len-num_spec-1 因此取到空块，D 侧读到零状态 → GDN NaN → MTP 接受率 0%
  - 修复后：none 模式保留原生 block_size（共享 backing 踩踏问题已由 C8-PTH full-attn 独立分配 backing 解决），align 模式行为不变

  注：该补丁是增量修复（相对"已含 C8-PTH 特性、未含本修复"的代码基线），需先应用完整 C8-PTH 特性补丁（eeab74c6）后再应用此补丁。
