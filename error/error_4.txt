  根因（已用算术证明）

  kv cache group sizes 日志：BF16 是 (896, 896, 896, 896)，C8 是 (1664, 8192, 8192, 8192)。

  hybrid 池里所有 group 共用一份 hybrid_backing 且 offset 都是 0，靠 block_id × page 定位。但 C8 的 section-major 布局让一个 kernel block 的 K   段只占 65536 字节（128×2×256），而 Mamba 的 state 按 page_size_padded = 1730560 定位。两个坐标系不同，必然穿插：

  ┌─────────────────┬────────────┬───────────────────────────┐
  │ full-attn block │ K 字节偏移 │     落进 Mamba state      │
  ├─────────────────┼────────────┼───────────────────────────┤
  │ 13              │ 851,968    │ state 0                   │
  ├─────────────────┼────────────┼───────────────────────────┤
  │ 52              │ 3,407,872  │ state 1                   │
  ├─────────────────┼────────────┼───────────────────────────┤
  │ 79              │ 5,177,344  │ state 2                   │
  ├─────────────────┼────────────┼───────────────────────────┤
  │ 103             │ 6,750,208  │ state 3 ← 本请求用的 slot │
  └─────────────────┴────────────┴───────────────────────────┘

  探针实测印证：chunk 2 时 slot=3 ssm_abs=27.79（干净），chunk 3 时同 slot ssm_nan=572 ssm_abs=nan。中间只发生了 full-attn 层的 KV 写入。

  BF16 下 full-attn 的 block 是 b × 1835008，与 Mamba 的 k × 1835008 同坐标系（block_size 都是 896），所以不错位。
